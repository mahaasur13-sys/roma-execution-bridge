# adapters/jev — sidecar-адаптер Jev (эпоха G-JEV-BRIDGE)

Ядро ROMA этот пакет **не импортирует**. Ни планировщик, ни шедулер, ни decision-gate, ни биллинг, ни Stripe/CloudPayments, ни раннеры задач на него не ссылаются. Полный контракт — `docs/spikes/G-JEV-BRIDGE.md`.

## Что это

Один вызов `POST https://api.typesafe.ai/v1/systemone` (модель `jev-1.13.0`) на входе `state` + три закрытых вопроса, на выходе `execute` / `confirm` / `abort` / `skip`. Адаптер не пишет план, не генерирует текст, не решает оплату, деплой, удаление и квоты и ничего не возвращает в ROMA — ядро его не зовёт.

## Запуск (вне ядра)

```bash
python -m adapters.jev.run --state-file state.json
python -m adapters.jev.run --state-file state.json --out decision.json
python -m adapters.jev.run --state-file state.json --model jev-latest   # только ручной smoke
```

Сеть возможна только когда одновременно заданы `JEV_ENABLED` (включён) и `TYPESAFE_API_KEY` (непустой). Иначе — no-op: адаптер возвращает `skip`/`disabled` и не открывает сокет. Ключ не логируется.

Коды выхода: `0` — только `execute` / `confirm` / `abort`; `4` — `skip` (нулевой код намеренно не отдаётся: внешний вызывающий принял бы «нет мнения» за разрешение); `2` — ошибка использования; `3` — state не прочитан; `5` — вердикт получен, но `--out` не записан (ошибка вывода: цель не тронута, частичного JSON не остаётся). Любой сбой адаптера (включая чужое исключение и падение SDK на конструкторе) гасится в `skip` с причиной: наружу исключение не выходит.

## Шкала `risk` и нецелые значения

`risk` — дискретный уровень `RISK_LEVELS = (1, 2, 3, 4, 5)`. Вне шкалы, нечисло, `bool` и не `finite` → уровень не назначается → `skip`. Ошибка разбора не выходит исключением из горячего пути.

Порядок фиксирован:

1. `bool` и `None` отсекаются до приведения. `True` — подкласс `int`; без этого гейта он стал бы уровнем 1 и разрешил `execute`.
2. Строка обрезается (`strip`). Пустая строка → `skip`. `float()` не удался → `skip`.
3. `math.isfinite` отсекает `NaN` и `±inf`, включая строки `"nan"`, `"inf"`, `"Infinity"`.
4. Диапазонный гейт по **сырому** значению: вне `[1, 5]` → `skip`. Округление раньше гейта запрещено: `0.6` иначе стало бы 1 и ушло в `execute`.
5. Прошедшее значение округляется `math.floor(x + 0.5)` (half-up). На этой положительной шкале ровно `.5` идёт к более рискованному уровню. `round()` не используется: у него half-even (`2.5 → 2`, `4.5 → 4`).
6. С действием сравнивается уже целый уровень и порог `risk_confirm = 3.5` (`level > 3.5`, то есть уровень ≥ 4).

Относительно прежнего `round()` action на этой шкале не меняется: `3.5` и там, и там становится 4 → `confirm`. Меняется сохраняемый уровень: `2.5` было 2, стало 3 (оба `execute`); `4.5` было 4, стало 5 (оба `confirm`); `1.5` остаётся 2. Потребитель, который читает уровень, а не только action, видит смену на `2.5` и `4.5`.

Относительно сравнения сырого `value > 3.5` (без округления) action меняется только в точке ровно `3.5`: сырое сравнение не проходит, уровень 4 проходит → `confirm`. Интервал `[3.5, 4)` меняет action относительно `floor` без half-up, не только точка `3.5`.

## Запись `--out`

`--out`: атомарная запись (temp рядом + `os.replace`). `OSError` на записи или `replace` → exit `5`, цель не тронута, temp удалён, вердикт не переклассифицируется, провайдер повторно не вызывается. Успех по-прежнему перезаписывает существующий файл. `BaseException` этим кодом не маскируется.

```bash

```
