### 2.3 Мультитенантность — ❌ P0

**Критическая находка:** `_admin_only()` **не проверяет, что пользователь — администратор**:

```python
def _admin_only(request: Request) -> dict:
    """Verify admin access — requires valid API key + tenant-demo."""
    api_key_raw = request.headers.get("X-API-Key")
    ...
    info = API_KEYS.get(api_key_raw)
    if not info:
        raise HTTPException(status_code=401, detail="Invalid API key")
    return info  # ЛЮБОЙ tenant проходит!
```

**Любой tenant со своим API-ключом может получить доступ к `/admin/*`.** Документация обещает проверку `tenant-demo`, но код её не делает.

**Утечка данных между tenant'ами:**
- `get_analytics_events()` не фильтрует по `tenant_id` — возвращает **все** события всех tenant'ов ❌
- `list_tenants()` возвращает **всех** tenant'ов ❌
- `get_analytics_overview()` агрегирует данные **всех** tenant'ов без разграничения ❌

**Проблема `/health`:** Вероятно, вызывает `db.get_tenant()` или другую операцию БД. Health-check должен быть максимально лёгким.

### 3.2 Нагрузка на БД

SQLite (WAL-режим) выдерживает ~100 одновременных read + 1 write. Для мультитенантного SaaS это узкое место при >50 конкурентных пользователях.

**Рекомендации:**
- При >100 RPS: мигрировать на PostgreSQL (уже доступен в sandbox для AstroFin)
- Добавить `PRAGMA cache_size = -20000` (20MB кэш)
- Добавить `PRAGMA mmap_size = 268435456` (256MB memory-mapped I/O)

### 3.3 Кеширование

Redis не используется в production. Есть только ссылки в `consistency/global_state_model.py` как концептуальный слой.

**Текущее состояние:** Всё чтение — напрямую из SQLite при каждом запросе.

### 3.4 Асинхронная обработка

67 `async def` функций. FastAPI полностью асинхронный. Прямых блокирующих вызовов I/O не обнаружено (кроме `time.sleep` в send_invitations.py — это CLI-скрипт, не API).
