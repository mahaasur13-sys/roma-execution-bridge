# Шаблон разметки shadow-датасета (для будущего пересчёта порогов)

Дата: 2026-10-16. Разметка выполняется **вручную** поверх накопленного
`JEV_SHADOW_LOG` (JSONL). Каждая запись `record()` уже содержит `point`, `choice`,
`confidence`, `verdict` (детерминированный), `observed_at` (+ point-специфичные поля).
К ним добавляются два поля разметки: `ground_truth` и `notes`.

## 1. Структура размеченной записи

```json
{
  "point": "R1",
  "tenant_ref": "t_80a707af7dc7",
  "choice": "anomaly",
  "confidence": 0.92,
  "verdict": "allowed",
  "observed_at": "2026-10-16T21:35:00+00:00",
  "ground_truth": "anomaly",
  "notes": "пачка из 200 однотипных submit за 1 минуту"
}
```

Способ: скопировать `JEV_SHADOW_LOG` в отдельный файл разметки и дописать
`ground_truth`/`notes` построчно (или вести отдельный labels-файл, ключ = `observed_at`).

## 2. Словарь `ground_truth` по точкам

| Точка | Допустимые `ground_truth` | Что означает |
|-------|---------------------------|--------------|
| R1 | `normal` / `anomaly` | было ли задание фактически аномальным/абьюзом (объём, паттерн, payload) |
| R3 | `compliant` / `violation` | было ли фактическое нарушение policy (квота/стоимость/custom) |
| R5 | `job_submit` / `job_status` / `billing` / `plugin_help` / `error_help` / `general` | верный интент сообщения |

## 3. Сколько размечать (первый этап)

- **Минимум 200 на точку** — порог из `G-JEV-BRIDGE-SPIKE-REPORT.md` (N ≥ 200),
  в идеале **сбалансированно** по классам (иначе agreement/flip-rate смещены).
- Первый «грубый» проход — **100–200 на точку**: достаточно, чтобы оценить порядок
  agreement/flip-rate и выявить систематические ошибки Jev.
- Для честных ECE/Brier нужен запас на корзину confidence (~30–50 примеров на корзину;
  при 5–6 корзинах это ~200+ на точку).

## 4. Что НЕ делаем на этом этапе

- Не меняем пороги (остаются заглушками до полного датасета).
- Не включаем cascade-флаги.
- Не трогаем R2.
