## 🔴 Known Issues (не исправлены в этой сессии)

### 1. Submit 500: `psycopg2.ProgrammingError: can't adapt type 'DecisionRequest'`
**Причина:** `gate.evaluate(dreq)` передаёт Pydantic-объект напрямую в psycopg2.  
**Где:** `main.py:880` → `cost/gate.py:evaluate()` → `db_adapter.py:insert_decision_request()`  
**Фикс:** заменить `await gate.evaluate(dreq)` на `await gate.evaluate(tenant_id=tenant_id, payload=payload.model_dump())`  
**Влияние:** критические — `/submit` не работает, биллинг не срабатывает через API.

### 2. PG Pool Lazy Init
**Симптом:** Health показывает `pg: false, status: uninitialized` пока кто-то не вызовет `_ensure_pool()`.  
**Фикс:** добавить `billing_ledger._pg._ensure_pool()` в `main.py` при старте приложения (on_event "startup").  
**Влияние:** низкое — пул инициализируется при первом обращении к ledger.

### 3. Billing/balance возвращает in-memory данные
**Причина:** `PGBillingLedger.get_balance()` падает в `_pg_execute` → `PGUnavailableError` → in-memory fallback.  
**Фикс:** тот же что и #2 — принудительная инициализация пула на старте.  
**Влияние:** среднее — данные в PG есть, но API их не видит.

### 4. Vast.ai не протестирован с реальными ключами
**Причина:** нет `VASTAI_API_KEY`.  
**Тест:** задать ключ в `.env`, переключить `ROMA_EXECUTION_BACKEND=vastai`, отправить GPU-job.  
**Влияние:** некритичное — backend gracefully degrades до local.
